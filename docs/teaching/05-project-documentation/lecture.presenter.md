Актуальность нормативной ссылки — подтверждённое соответствие обозначения, редакции, статуса и области применения документа поставленной задаче.

## Слайд 12. Как строится решение

<!-- source-slide: 05-project-documentation-c1-mechanism -->

Официальный статус и применимость к документу проверяются раздельно.

Показ: нажмите «Развернуть схему», затем «Обзор». Официальный статус и применимость к документу проверяются раздельно. Для «Карточка стандарта» сопоставлены что подтверждает: Обозначение, редакцию, статус; чего не подтверждает: Полноту конкретного описания API. Для «Стандарт стадий» сопоставлены что подтверждает: Порядок работ в своей области; чего не подтверждает: Состав уже реализованной формы. Для «Выданный шаблон API» сопоставлены что подтверждает: Обязательные разделы данного результата; чего не подтверждает: Работоспособность реализации.

Показ: «Далее по схеме», шаг 1. Найти точное обозначение. Проверены название, редакция и официальный статус. Номер в старой методичке не заменяет действующую карточку.

Показ: «Далее по схеме», шаг 2. Проверить область. Нужен документ на реализованную функцию. Описание стадий и описание поведения операции решают разные задачи.

Показ: «Назад по схеме» возвращает предыдущее объяснение; «Обзор» — исходную таблицу или схему. Закройте окно клавишей Escape.

**Подготовка:** Открыть исходный «Обзор». Это пошаговое объяснение условных данных; обращения к реальному серверу здесь не выполняются.

Почему каждый результат следует из данных? Что изменится в сравнительном условии и что сохранится?

**Разбор для преподавателя:**

Исходная таблица: Работа | Минуты.
Бюджет | 16
Связь с тестом | 5
Сверка примеров | 4
Экспорт и открытие | 3

Шаг 1. Восстановите последнее звено указанной цепочки BR9 → поле → метод → тест.
В поле «ID теста» введите T2. Нажмите «Проверить шаг 1». На экране: «Первый результат проверен. Теперь отдельно выполните второй шаг.». В таблице результата появится это значение со статусом «Проверено».
Почему: Последнее звено заданной цепочки BR9 → signature_file → complete → T2 является потерянным тестом.
При расхождении поле показывает инструкцию и требуемый формат: ID теста из условия. Исправьте значение и повторите проверку.

Шаг 2. Вычтите из бюджета все три обязательные работы.
В поле «Резерв, минут» введите 4. Нажмите «Проверить шаг 2». На экране: «Оба результата проверены. Сопоставьте их с исходными данными и обоснуйте вывод.». В таблице результата появится это значение со статусом «Проверено».

При расхождении поле показывает инструкцию и требуемый формат: Целое число минут без единиц. Исправьте значение и повторите проверку.

Изменённое условие: Если повторное открытие потребует ещё 2 минуты. Обязательные работы займут 14 минут; резерв уменьшится до 2. Связь с T2 сохраняется.
Граница: Бюджет условный; фактический формат сдачи берётся из выданного задания.
Изменение второго ответа скрывает разбор. Изменение первого дополнительно очищает второй результат: его требуется получить заново. Возврат: «Вернуться к слайду» или Escape.
