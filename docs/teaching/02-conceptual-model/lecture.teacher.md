## Первичный ключ

Первичный ключ (PK) — выбранный кандидатный ключ таблицы: минимальный набор атрибутов, однозначно идентифицирующий строку; значения PK не допускают NULL.

Первичный ключ выбирается из допустимых уникальных идентификаторов и запрещает пустое значение. Суррогатный числовой ID удобен, но сам по себе не обеспечивает уникальность бизнес-номера. Для номера заявки при необходимости добавляют ограничение UNIQUE. Изменяемое название клиента плохо подходит для связи; переименование не должно менять идентичность.

## Связи и выводы темы

Первичный ключ удерживает идентичность строки, внешний — допустимость ссылки. Нормализация размещает каждый факт у его определителя, а политика удаления сохраняет нужную историю. Ни нормальная форма, ни сам FK не выбирают за нас бизнес-правило удаления.

Результат: два визита связаны с одной заявкой; технические ключи не зависят от отображаемого номера и названия. Результат: ссылка на заявку контролируется FK, а список запчастей заменён двумя проверяемыми строками. Результат: название запчасти и текущий адрес не дублируются; исторический адрес сохраняется лишь при явно заданной потребности. Результат: M:N представлена строками с количеством; дубль пары контролируется; завершённая история не удаляется вместе с инженером.
