## Слайд 17. Первичный ключ

<!-- source-slide: 02-conceptual-model-c2-definition -->

Первичный ключ (PK) — выбранный кандидатный ключ таблицы: минимальный набор атрибутов, однозначно идентифицирующий строку; значения PK не допускают NULL.

Первичный ключ выбирается из допустимых уникальных идентификаторов и запрещает пустое значение. Суррогатный числовой ID удобен, но сам по себе не обеспечивает уникальность бизнес-номера. Для номера заявки при необходимости добавляют ограничение UNIQUE. Изменяемое название клиента плохо подходит для связи; переименование не должно менять идентичность.

**Подготовка:** Данные Field Service условные. Использовать состояние и значения текущего экрана; не подменять их данными самостоятельного случая.

Результат: M:N представлена строками с количеством; дубль пары контролируется; завершённая история не удаляется вместе с инженером.

**Подготовка:** Данные Field Service условные. Использовать состояние и значения текущего экрана; не подменять их данными самостоятельного случая.

**Разбор для преподавателя:**

Какое решение изменится при других исходных данных?
Новый повторный визит создаёт строку visit и не новую заявку. request_id не становится PK визита.

Где остаётся допущение и кто его подтвердит?
Зависимости и смысл исторического снимка нужно подтвердить владельцу данных; одинаковые значения сегодня не доказывают одинаковую семантику.

Как показать, что результат выдерживает отрицательный пример?
Вставка позиции с несуществующим visit_id должна быть отклонена. Отдельно проверяем, что архивирование инженера сохраняет завершённые визиты.
